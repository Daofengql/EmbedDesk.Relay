# 控制台、账号与带宽

打开 `https://HOST/console/`，使用首次配置的管理员登录。控制台将节点管理、账号与设备归属分开：节点公共令牌负责简单准入过滤，账号负责资源管理，设备连接仍需对端密码或人工授权。

## 首次登录后先做什么

1. 在「运行概览」确认存储类型与进程状态。
2. 打开「中继接入」→「中继设置」，核对节点名称和 HTTPS 根地址。
3. 输入新账号默认带宽，例如 `10` Mbps；按需开启公共令牌过滤。
4. 保存并复制当前连接代码，导入桌面客户端，重新上线验证。
5. 如需自助注册，修改启动配置的注册开关并重建中继；随后用普通用户完成一次验证码注册和设备绑定。
6. 管理员创建成功后移除 Bootstrap 凭据，并备份数据库与私有配置。

## 运行概览怎么看

管理员首页优先显示 CPU、系统内存、当前中继 RX / TX 和系统负载，约每轮请求完成后 2 秒继续刷新。普通用户 / 访客只看到自己的设备与资源，不返回主机指标。

![管理员运行概览演示](/images/console-overview.png)

*这是 Hyper-V Linux 虚拟机中的独立演示实例：使用 SQLite、未启用 Redis，页面处于空闲状态，因此转发速率为 0。截图用于说明布局与字段，不是容量或公网性能实测。*

| 指标 | 正确含义 |
| --- | --- |
| CPU、系统内存 | 主机当前采样；不能直接代表某个用户造成的负载 |
| 1 / 5 / 15 分钟负载 | 系统运行队列负载，不是百分比 |
| RX / 接收 | 客户端发往中继的加密数据 `body` |
| TX / 发出 | 中继成功发往客户端的加密数据 `body` |
| 合计带宽 | RX + TX；一次转发两端分别计量 |
| 累计数据 | 当前进程启动后累计，重启归零 |

未知系统指标显示「暂不可用」，不是伪造为 0。数据不包括其他网卡业务或 WebSocket / TLS 包头，不能当成网卡流量计费凭据。当前没有历史时序库、自动告警和跨实例汇总。

## 账号与角色

| 角色 | 可以做什么 | 不可以做什么 |
| --- | --- | --- |
| 系统管理员 `admin` | 全部账号、设备、会话、节点设置、审计 | 不能禁用或降级最后一个可用管理员 |
| 注册用户 `user` | 绑定无主设备，管理自己的设备与相关会话 | 不能修改其他用户配额或节点设置 |
| 只读访客 `guest` | 查看管理员分配的关联资源与公共节点信息 | 不能注册设备归属、写设置或关闭会话 |

所有登录角色都能复制节点公共连接代码、修改自己的密码和退出登录。访客是有账号的只读控制台用户，和不归属任何账号的匿名设备不是同一个概念。

### 管理员创建用户

进入「用户管理」→「创建用户」，填写用户名、初始密码、角色、设备上限和账号总带宽。创建时带宽初值取节点当前默认值，管理员可在提交前调整。

编辑已有账号时，密码留空会保留原密码。修改密码、角色或禁用状态会撤销该账号旧控制台会话；修改带宽会断开其关联设备。重置密码不会自动把新密码发送给用户，需要使用自己的可信渠道交付。

![编辑演示用户的账号配额](/images/console-user-quota.png)

*示例给研发演示账号设置 20 Mbps、10 台设备上限；20 Mbps 是账号下全部设备共享的双向总预算。截图中的重置密码留空，表示保留原密码。*

### 开放自助注册

设置 `EMBEDDESK_REGISTRATION_ENABLED=true`，重建 / 重启中继。Compose 示例：

```sh
docker compose up -d --no-deps --force-recreate server
```

登录页出现注册入口。新账号固定为 `user`、设备上限 5，使用当前节点默认带宽作为账号总额度。注册要求一次性图片验证码，有效 3 分钟；提交失败时刷新验证码后再试。

| 字段 | 规则 |
| --- | --- |
| 用户名 | 3–48 位小写 ASCII 字母、数字、点、下划线或短横线，首位为字母或数字 |
| 密码 | 12–72 个 UTF-8 字节；汉字通常 3 字节 |
| 显示名称 | 用于列表辨识，不替代登录用户名 |

::: tip 当前没有邮件验证或找回密码
请保留至少一个可以正常登录的管理员账号。Bootstrap 不会重置已有账号；当前也没有邮箱验证、自动找回、计费或套餐购买功能。
:::

## 公共准入令牌：刷新后怎么交付

每个节点只有一份公共 Token，全部客户端共用。它只用于简单过滤扫描，不是个人登录凭据、设备归属证明或访问其他设备的授权。

管理员在「中继接入」点击「刷新令牌」并确认，服务器随机生成并启用新令牌；不能手动输入。保存普通节点设置不会顺带轮换它，关闭过滤则不再要求公共 Token。

建议按以下顺序刷新：

1. 确认目前是否有客户端正在重新上线。
2. 点击「刷新令牌」，阅读确认框的影响范围后提交。
3. 复制新连接代码，分发给使用该节点的客户端。
4. 客户端在节点设置重新导入，下一次注册使用新值。

::: warning 刷新不会踢掉全部在线设备
现有 WebSocket 保留；旧令牌在后续注册失败。若目标是立即阻止某个账号或设备，请使用禁用操作，而不是只刷新公共 Token。连接代码是 Base64 编码并包含公共令牌，不是加密保险箱。
:::

## 设备绑定与管理员分配

先让桌面设备上线，控制台才有该节点的设备登记。在「设备管理」点击「绑定设备」，输入客户端连接中心显示的 12 位十六进制设备 ID，确认绑定。

![设备列表与归属演示](/images/console-devices.png)

*列表中的账号与设备均为虚构演示数据，用于说明在线状态、接入权限、所属用户和更多操作入口。*

- 设备尚无归属：可绑定到自己的账号，计入设备上限。
- 已属于自己：重复绑定不会重复占用名额。
- 已属于他人：普通用户不能领取，需由管理员核对并分配。
- 账号设备已满：先清理不再需要的登记，或由管理员调整数量上限。

管理员通过设备行末三个点 →「分配所属用户」调整归属；清空后恢复匿名设备。绑定、转移或清空归属会断开相关设备，重连后应用新预算。

::: warning 设备 ID 绑定的边界
知道无主设备 ID 即可领取，当前流程不证明真实持有硬件。不要把设备 ID 当成强所有权凭据；对端设备访问仍走客户端密码或人工授权。人工授权依赖可信中继和传输链路。
:::

## 可用带宽如何计算

匿名设备每台独立使用节点默认值。绑定后，**同一账号全部设备、全部会话的上传和下载合计共享一个总预算**，不是每台各得一份。

| 示例 | 结果 |
| --- | --- |
| 节点默认 10 Mbps，两台匿名设备 | 每台分别使用默认预算 |
| 用户账号 10 Mbps，名下两台设备对外转发 | 两台合计共享 10 Mbps 双向预算 |
| 同账号两台设备互传 | 每端 RX / TX 都计入同一账号预算，不能按单端测速反推总额度 |
| 局域网直连成功 | 直连业务不消耗中继配额 |

界面按 1000 换算 bps / Kbps / Mbps / Gbps；例如输入 4096 Mbps，显示为 4.096 Gbps。控制台输入单位为 Mbps，启动配置单位为 bits/s。

### 改默认还是改单用户

| 操作 | 已有账号 | 在线设备 |
| --- | --- | --- |
| 修改节点默认带宽 | 不覆盖 | 匿名设备下次重连应用新值 |
| 修改某个用户总配额 | 只改此账号 | 断开相关设备，重连后共享新预算 |
| 转移设备归属 | 使用新所属账号预算 | 断开被转移设备 |

新用户默认带宽和单用户额度可分别维护，避免为提高一个用户的额度而放大所有新注册用户的默认值。

## 批量管理：先选中，再确认影响

用户、设备与中继会话列表均支持**当前页**多选。先勾选行或「全选当前页」，再打开「批量操作」；未选择时按钮不可用。批量接口每次接受 1–100 项，不会隐含选中其他分页结果。

![设备批量操作演示](/images/console-batch.png)

*演示实例中的批量菜单。实际执行前核对选中数量、当前筛选条件和确认框描述。*

| 列表 | 可执行批量操作 |
| --- | --- |
| 用户（管理员） | 启用 / 禁用、设置账号总带宽、设置设备上限 |
| 设备 | 启用 / 禁用、断开、删除登记；管理员还可分配或清空归属 |
| 中继会话 | 关闭所选会话 |

后端先校验整批角色、归属和规则，失败不产生部分写入；会话中已结束的项会标记跳过。读写操作依然受当前角色限制，访客不显示写操作。

### 断开、禁用、删除不能混用

| 操作 | 作用 | 客户端可能自动回来吗 |
| --- | --- | --- |
| 断开设备 | 结束当前设备连接和相关会话 | 可以，仍符合准入条件时会重连 |
| 关闭会话 | 结束所选设备间会话 | 设备保持在线，后续可重新发起 |
| 禁用设备 / 用户 | 断开并阻止后续认证 | 禁用解除前不能正常接入 |
| 删除登记 | 删除设备记录，释放账号设备名额 | 可以重新注册为匿名设备 |

::: tip 想阻止接入就用禁用
删除登记是清理归属和名额，不是封禁。看到设备删除后再次出现，先确认客户端是否仍运行并自动注册。
:::

## 审计与交付前检查

管理员在「审计日志」查看账号、设备、会话和节点的管理操作。审计不保存密码、公共 Token、认证头、候选地址或转发正文，也不替代数据库备份。

完成一次配置后，建议检查：当前账号能重新登录、节点代码指向正确 HTTPS 根地址、普通用户只看到自己的资源、匿名与绑定设备带宽符合计划，以及危险批量操作的确认数量正确。
