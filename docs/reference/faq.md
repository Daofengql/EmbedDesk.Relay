# 常见问题与故障定位

先按“源站 → 存储 → HTTPS → 登录 → 设备转发”的顺序检查，不要一次修改多层配置。以下命令默认在 Compose 项目目录执行，`HOST` 替换为真实域名。

## 第一步：判断坏在哪一层

| 检查 | 结果 | 下一步 |
| --- | --- | --- |
| `curl http://127.0.0.1:7080/health` | 连接失败 | 看进程、端口和容器 |
| 同机 `/health` 成功，`/ready` 503 | 存储未就绪 | 看 MySQL / Redis |
| 同机 `/ready` 成功，域名失败 | 代理 / DNS / TLS | 看 Nginx / 宝塔 |
| 域名 `/ready` 成功，登录失败 | 认证配置 | 看 Cookie / Origin / 账号 |
| 登录正常，设备不上线或掉线 | 设备链路 | 看准入、WSS、证书和设备状态 |
| 上线授权正常，但服务打不开 | 共享目标 / 客户端 | 看已发布服务、端口占用与目标网络 |

需要保留错误详情时，只截取必要日志，不附带 `.env`、Cookie、密码或完整设备列表。

## 容器或 systemd 服务不断退出

**现象：** `server` 显示 Restarting，或 systemd 反复启动。源站 `/health` 无法访问。

**定位：**

```sh
docker compose ps -a
docker compose logs --tail=100 server
docker compose logs --tail=100 mysql redis
```

systemd 改用：

```sh
sudo systemctl status embeddesk-server --no-pager
sudo journalctl -u embeddesk-server -n 100 --no-pager
```

**处理：**

- 出现 `configuration failed`：按错误核对 JSON 字段、布尔值、端口、URL 和带宽范围。
- 出现 `database initialization failed`：该提示不区分所有内部初始化原因，依次检查数据库连通、账号权限、Redis URL，以及空库 Bootstrap 条件；不要仅据这句话认定 MySQL 损坏。
- 出现 `HTTP listener failed`：检查 `ss -ltnp`，确认监听地址存在且端口未占用。
- 出现 `Exec format error`：Linux 架构与二进制不匹配，按 `uname -m` 重新选择 `amd64` / `arm64`。

::: warning 不要清空数据重试初始化
Bootstrap 不是密码重置器，MySQL 镜像环境变量也不修改已初始化密码。删除数据库或 `down -v` 会丢失账号、归属和设置，不能作为一般排查步骤。
:::

## `/health` 正常，但 `/ready` 返回 503

**现象：** 进程响应，`/ready` 返回 `{"status":"unavailable"}`。

**定位：** 检查 MySQL / Redis 日志、健康状态、连接地址和主机磁盘。Compose 中数据库主机名是 `mysql`、Redis 是 `redis`；容器内的 `127.0.0.1` 指的是容器自身。

**处理：** 修复连接与认证，确认中继账号拥有专用库权限。已配置 Redis 时，服务不会跳过故障存储而继续认证；不需要 Redis 的单机方案应按计划删除 URL 并重启，而不是靠 Redis 断线“自动回退”。

## 域名访问 502、404 或仍是默认站点

**现象：** 本机就绪正常，但公网打开不对。

**定位：**

```sh
curl --fail --silent --show-error http://127.0.0.1:7080/ready
curl --fail --silent --show-error https://HOST/ready
```

**处理：**

- 502：代理目标端口是否与宿主映射一致；Nginx 若在容器内，不能用其自身回环访问宿主服务。
- 默认站点：检查 DNS 的 A / AAAA、Nginx `server_name` 和宝塔绑定域名。
- 404：检查根路径代理是否被其他 `location`、静态文件规则或额外 `/relay/` 前缀覆盖。

修改后用现有站点管理器检查并重载。宝塔站点应从面板创建与维护，不另建同域名的面板外配置。

## 证书错误或宝塔签发失败

**现象：** 浏览器证书警告，客户端 TLS 校验失败，或面板证书验证失败。

**定位：** 核对访问主机名、证书有效期与完整链；检查 A / AAAA 是否都指向当前主机。HTTP 验证检查 80 端口及面板的验证路径，DNS 验证检查插件授权和记录。

**处理：** 使用证书覆盖的真实域名，更新正确证书链。不要关闭客户端 TLS 校验来掩盖错误；中继自己不读取证书，继续由 Nginx / 宝塔维护续期。详见 [HTTPS 部署](../deployment/nginx.md)。

## 控制台返回 503，提示前端资源不可用

**现象：** `/health` 正常，控制台资源没有嵌入。

**定位：** 确认程序是否仅做过普通 `go build`，未先构建 `www/dist`。

**处理：** 使用 `build.ps1` / `build.sh` 或 Dockerfile 完整构建，重新部署包含前端的二进制。运行目录不需要额外拷贝 React 源码；提供源码旁置不能替代 `go:embed`。见[构建与验证](../development/index.md)。

## 页面能打开，登录后又回到登录页

**现象：** 账号密码看似正确，但 `/auth/me` 仍未登录。

**定位：** 检查浏览器实际使用的是 HTTP 还是 HTTPS、Cookie 的 Secure 属性、会话存储是否可用；域名与 IP 混用也不会共享 Cookie。

**处理：** 公网统一访问 `https://HOST/console/`，`cookieSecure=true`。可信本机 HTTP 测试才设为 `false`。已初始化 HTTP 节点迁移 HTTPS 涉及数据库公开地址与 Cookie 同步，按[迁移流程](../deployment/nginx.md#迁移已有-http-节点到-https)处理，不能只改一个环境变量。

## 能浏览，但保存设置返回 403

**现象：** GET 列表正常，POST / PATCH 提示 cross-origin 或 CSRF 错误。

**定位：** 检查浏览器地址、数据库中节点公开 URL、Nginx 转发的 Host 是否一致；确认没有在旧域名标签页继续提交，或使用过期会话。

**处理：** 保留代理 Host，使用节点当前 HTTPS origin，重新登录。手工 API 请求需正确的会话 Cookie、JSON Content-Type 与 `X-CSRF-Token`；不要通过关闭校验排查。

## Bootstrap 改了密码，管理员仍登录不了

**现象：** 修改 `.env` 的初始化密码并重启，原账号密码没有变化。

**定位：** 账号表已不为空时，Bootstrap 有意不重置任何已有用户。

**处理：** 使用原有管理员登录，在「用户管理」编辑账号或重置密码；管理员自己的密码也可从账号菜单修改。当前没有邮箱找回功能。只有全新空库才使用 Bootstrap；其用户名与密码必须同时提供，密码 12–72 个 UTF-8 字节。

## 注册入口不显示、验证码反复失效或返回 429

| 现象 | 定位 | 处理 |
| --- | --- | --- |
| 没有注册入口 | 启动开关是否 `false`，环境是否应用 | 设置 `EMBEDDESK_REGISTRATION_ENABLED=true` 并重建中继 |
| 注册 403 | 节点不允许注册 | 联系管理员确认开放策略 |
| 验证码失效 | 一次性消费、超过 3 分钟或提交失败后复用 | 获取新图后重新输入 |
| 用户名冲突 409 | 相同用户名已存在 | 更换用户名或使用登录 |
| 登录 / 注册 429 | 来源或用户名尝试过多，也有实例级保护 | 停止重试，按 `Retry-After` 等待；常见窗口为 15 分钟 |
| 503 | 会话、验证码或登录保护存储异常 | 检查 MySQL / Redis，不绕过验证码 |

反向代理后的请求不任意信任 `X-Forwarded-For`，多个用户可能共享代理来源限额。不要简单把任何客户端自报的转发头设置为可信。

## 客户端能导入节点，但无法上线

**现象：** 节点出现在列表，设备注册或 WebSocket 连接失败。

**定位：** 检查当前连接代码、HTTPS 根地址、公共准入过滤、证书和设备 / 账号禁用状态。`/health` 不验证准入 Token，因此测速正常不代表注册一定通过。

**处理：** 从控制台重新复制代码；令牌刷新后旧代码不能用于后续注册。地址不要含 `/console/`。检查设备行是否禁用、所属账号是否禁用，Nginx 是否保留 WebSocket Upgrade。无凭据 curl `/v1/channel` 返回 401 是正常行为，不能作为完整 WSS 验收。

## 上线后固定几十秒掉线

**现象：** 控制台能使用，但设备长连接周期性断开。

**定位：** 检查 Nginx / 宝塔的 WebSocket 开关、Upgrade 头、读写超时和中间代理限制。协议存在应用心跳与 Ping / Pong，超时 75 秒。

**处理：** 按示例保留 HTTP/1.1、Upgrade、Connection，并使用 120 秒代理读写超时、关闭缓存。保持双端连接超过 2 分钟验证。不要把无限加大超时作为唯一修复，真实断线仍需要客户端清理与退避重连。

## 绑定失败、批量操作不能执行

| 现象 | 原因与处理 |
| --- | --- |
| 设备 ID 不存在 | 先让该设备接入同一个节点，再复制客户端显示的 12 位 ID |
| 已被其他账号持有 | 普通用户不能领取，由管理员核对并分配 |
| 设备数量超限 | 调整上限或删除不再使用的归属登记 |
| 批量按钮不可点 | 先选择当前页的行；访客无写权限 |
| 批量整批失败 | 核对其中是否有无权限、超配额或受保护的最后管理员；不会部分写入 |
| 改归属后设备断线 | 预期行为，重连后应用新账号预算 |
| 删除后设备又出现 | 运行中的客户端可重新注册为匿名设备；阻止接入用禁用 |

## 带宽与预期不同

**现象：** 给账号 10 Mbps，两台设备没有各得到 10 Mbps；或监控合计高于业务净流量。

**定位与处理：** 账号额度是全部设备双向合计共享，匿名设备才各自独立使用默认值。同账号互传按每端 RX / TX 计入同一预算；监控只计加密 `body`，一次转发分别计接收与成功发出。局域网直连不使用中继配额。单位按 1000 换算，4096 Mbps = 4.096 Gbps。

修改节点默认带宽不影响已有用户，在线匿名设备需重连；修改单用户配额则断开其关联设备。详见[账号与带宽示例](console.md#可用带宽如何计算)。

## 为什么不能直接扩成多实例或交给 Pages

当前设备、会话和账号共享限速在单进程内存中，共用 MySQL / Redis 不会形成集群。随机负载均衡会让相关设备落到不同进程，不能直接扩容。

GitHub / Cloudflare Pages 只能托管静态内容。反向代理只转发请求，不会把中继的连接管理和 WebSocket 数据处理从 Go 源站移走；中继仍需要运行在服务器上。
